# Keamanan & privasi

| Area | Kontrol |
|---|---|
| **Autentikasi** | Password di-hash **scrypt** (N=2¹⁵, parameter tersimpan → dapat dinaikkan). Kebijakan: ≥ 12 karakter, bukan yang umum, tidak memuat email/nama. Waktu respons disamakan untuk akun tak dikenal (anti user-enumeration). |
| **2FA (TOTP, RFC 6238)** | Opsional per akun; Super Admin dapat **mewajibkannya untuk Admin/HR & Super Admin** (tanpa 2FA, semua halaman/API selain pengaturan 2FA ditolak). Rahasia dienkripsi **AES-256-GCM** (`DATA_ENCRYPTION_KEY`). Setelah password benar akun ber-2FA **tidak mendapat sesi** — hanya *tantangan* sekali pakai (5 menit, hash saja yang disimpan, maks. 5 percobaan). Kode TOTP **tidak dapat dipakai ulang** (langkah waktu diklaim atomik di database; kode lama/mundur ditolak). 10 **kode pemulihan** sekali pakai (hash SHA-256; sekali dipakai dihanguskan secara atomik). Percobaan salah dibatasi per pengguna (5 / 15 menit). Mengaktifkan/mematikan 2FA mencabut sesi lain; mematikan & membuat ulang kode pemulihan memerlukan password **dan** kode. Reset 2FA akun lain hanya Super Admin (tidak untuk diri sendiri), mencabut semua sesinya, dan tercatat di audit. |
| **Lupa password mandiri** | Tautan acak 256-bit, **hanya hash-nya** disimpan, berlaku 30 menit (dapat diatur), **sekali pakai** (diklaim atomik — pemakaian paralel hanya satu yang menang), hanya satu tautan aktif per akun. Respons **identik** untuk email terdaftar/tidak (anti-enumerasi; pengiriman tidak di-await sehingga waktu respons sama). Dibatasi: 3 permintaan/jam per email, 10/jam per IP; percobaan pemakaian token dibatasi. Akun ber-2FA **wajib menyertakan kode** saat reset (email saja tidak melewati 2FA). Sukses → semua sesi dicabut, notifikasi ke pemilik akun. Token tidak pernah masuk antrean notifikasi atau log. |
| **Sesi** | Cookie `HttpOnly`, `SameSite=Lax`, `Secure` + awalan `__Host-` di HTTPS. Token acak 256-bit; **hanya SHA-256-nya** disimpan. Idle 8 jam / absolut 7 hari; dicabut saat logout, ganti/reset password, ganti peran, nonaktif, atau perubahan 2FA. |
| **Brute force** | Batas percobaan login per email (5/15 menit) dan per IP, atomik di database; dikunci sementara. Kode 2FA, pesan uji, reset password, dan penolakan lokasi memakai mekanisme yang sama. |
| **Otorisasi (RBAC)** | Matriks di `src/lib/permissions.ts`, **ditegakkan di service layer** (bukan hanya menu). Karyawan: `employeeId` selalu dari sesi, tidak pernah dari input; data orang lain → 403/404. Halaman terlarang menjawab 404. HR tidak dapat memproses pengajuan cuti/lembur **miliknya sendiri**; hanya Super Admin menyetujui/membatalkan gaji, mengubah aturan penggajian/BPJS/PPh 21, mengelola kebijakan keamanan. |
| **CSRF** | Cookie SameSite + pemeriksaan header `Origin` pada semua permintaan yang mengubah data. Endpoint mesin-ke-mesin `/api/internal/deliveries` memakai `Authorization: Bearer` (`CRON_SECRET`, perbandingan waktu-konstan) dan mati bila rahasia tidak diatur. |
| **Header** | CSP ketat, `X-Frame-Options`, `nosniff`, `Referrer-Policy`, HSTS (produksi). `Permissions-Policy`: kamera/mikrofon mati; geolokasi hanya `self`. |
| **Validasi** | Zod di server untuk setiap masukan; `CHECK`/unik/trigger di database sebagai lapis kedua (jadwal, pecahan 0,5 hari, lembur, tinjauan lokasi, outbox). Kesalahan internal tidak membocorkan detail. |
| **Data sensitif** | Nomor rekening & rahasia 2FA dienkripsi **AES-256-GCM**; hanya 4 digit terakhir rekening di layar/slip/ekspor; membuka nomor lengkap dicatat di audit. Slip: rekening tidak pernah lengkap. Respons berkas `private, no-store`. Email/WhatsApp **tidak pernah memuat angka gaji**; alamat/nomor tujuan disamarkan pada layar admin. |
| **Pengiriman notifikasi** | *Transactional outbox*: pesan masuk antrean dalam transaksi yang sama dengan peristiwanya (tidak ada pesan tanpa peristiwa, tidak ada peristiwa yang kehilangan pesan). Klaim baris atomik (`FOR UPDATE SKIP LOCKED`) → tiap pesan terkirim tepat sekali walau banyak pekerja; percobaan ulang bertahap (1→60 menit, maks. 5 kali) lalu `FAILED` (terlihat & dapat diantre ulang oleh Super Admin). Pengguna yang dinonaktifkan/mematikan saluran dilewati. Kredensial SMTP/WhatsApp hanya dari environment. |
| **Integritas lokasi** | Opsional. Koordinat dibaca **sekali** saat check-in/out. Penilaian berlapis dan dicatat (`location_checks`): kesegaran pembacaan (jam perangkat yang sama), akurasi/presisi tidak wajar, titik persis di pusat, koordinat identik berulang/antar karyawan (hanya akurasi setara-GPS), perpindahan mustahil (>250 km/jam), perangkat baru/dipakai bergantian (cookie perangkat HttpOnly, hanya hash disimpan), dan **jaringan kantor** (IPv4/IPv6/CIDR; hanya bermakna bila `TRUST_PROXY=true` — pengaturan menolak daftar jaringan tanpa itu; alamat klien diambil dari entri `X-Forwarded-For` yang **ditambahkan proxy tepercaya** (dari kanan, `TRUST_PROXY_HOPS`), bukan entri kiri yang bisa dikirim klien sendiri; port aplikasi tidak boleh terjangkau langsung dari internet). Mode: mati / tandai / tolak. Penolakan dicatat, HR diberi notifikasi, antrean tinjauan wajib berkomentar & masuk audit. **Tidak menjamin anti-manipulasi** (lihat KEPUTUSAN-BISNIS). Tidak ada pelacakan berkelanjutan, tidak ada selfie. Disimpan hanya bila fitur lokasi aktif. |
| **Unggahan** | Tipe diverifikasi dari **isi berkas** (magic bytes), bukan ekstensi; SVG ditolak; batas ukuran; akses berkas dibatasi (foto: admin/pemilik; lampiran: peninjau/pengunggah). |
| **Ekspor** | Sel berawalan `= + - @` dinetralkan (CSV/Excel injection). Ekspor laporan dicatat di audit. |
| **Audit** | `audit_logs` append-only di level database (trigger). Mencatat perubahan karyawan, absensi & koreksi, pengajuan cuti/lembur, saldo, jadwal, komponen, penggajian, **konfigurasi BPJS/PPh 21**, pengaturan keamanan, akun, login/logout/gagal, **2FA, reset password, tinjauan lokasi**, ekspor. |
| **Integritas gaji** | Slip terbit & item/rincian di luar Draf dikunci trigger; alur status divalidasi database; deteksi data basi (termasuk perubahan persetujuan lembur); riwayat koreksi absensi & buku saldo cuti append-only; pengajuan lembur/cuti yang sudah diputuskan beku. |
| **Rahasia** | Hanya dari environment. Seed produksi tanpa password default. Akun demo ditandai `isDemo` + banner; seed demo menolak produksi/host non-lokal/database berisi. |
| **Cadangan** | Skrip dengan verifikasi arsip + checksum; pemulihan menolak menimpa tanpa konfirmasi (lihat DEPLOYMENT). |

## Catatan & batasan yang perlu Anda ketahui
- Tidak ada SSO. 2FA hanya TOTP (tanpa SMS/WebAuthn).
- Enkripsi aplikasi hanya untuk nomor rekening dan rahasia 2FA; data lain (gaji, alamat) dilindungi akses & enkripsi disk/cadangan yang Anda siapkan di infrastruktur.
- Kehilangan `DATA_ENCRYPTION_KEY` membuat nomor rekening **dan rahasia 2FA** tak terbaca (pengguna ber-2FA perlu direset oleh Super Admin).
- Dependensi: `npm audit` melaporkan kerentanan pada rantai `prisma` CLI (`deepmerge-ts`) dan `exceljs`→`archiver`→`glob`/`minimatch` — alat build / pembuat ekspor, bukan jalur permintaan yang menerima masukan pengguna. Paket baru (`nodemailer`, `qrcode`) tidak menambah temuan.
- Pindai dan pembaruan dependensi rutin tetap diperlukan; pertimbangkan uji penetrasi independen sebelum menyimpan data nyata.
